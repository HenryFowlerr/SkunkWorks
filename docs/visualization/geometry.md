# Bend diagram geometry

The first supported family is one flat sheet divided into a tree of rigid planar panels by straight bends. Coordinates are millimetres in one common flat XY plane. The reference face points toward +Z. A bend rotates the child panel and all descendants around the hinge axis, while the parent panel remains fixed relative to its own parent.

## Rotation and sequence convention

Hinge.axisStartMm to Hinge.axisEndMm gives the directed in-plane axis. A positive foldRotationDeg.value follows the right-hand rule about that direction; negative values rotate the other way. The renderer never changes this sign because of camera orbit. finishedAngle is source-facing shop language and is deliberately separate from the signed fold rotation used by the geometry engine.

The steps array is the sequence. At step index n, indices below n are fully folded, index n uses activeStepProgress from 0 to 1, and later bends remain flat. completedStepCount is an integer from 0 through steps.length; progress must be zero when all steps are complete. Stable bend IDs identify folds across reorderings.

Each bend can be applied once and must map to a hinge with a known signed angle. The panel graph must be a connected tree with one root. Hinge endpoints must lie on a boundary edge of both connected panels within 0.5 mm, matching the shared PanelModel schema. Panels require finite, non-degenerate, non-self-intersecting polygons. The pure evaluator reports typed GeometryError codes; missing input never becomes a zero rotation.

Matrices are column-major 4x4 transforms using column vectors, with translations in millimetres. This allows tests, editors and a Three.js renderer to consume one deterministic transform format.

## Limits

The diagram extrudes rigid panels by the authored sheet thickness for visual legibility. It does not model bend radii, material deformation, springback, collision, tool clearance, press motion, or manufacturability. Do not use the schematic as a measurement surface or machine instruction.

## Demonstration data

public/demo is generated by src/features/visualization/scripts/generate_demo_assets.py. It contains two original synthetic sensor-mount variants with matching drawing sheets, portable bend manifests, and self-contained GLB final models. The two variants deliberately differ in blank dimensions, signed folds and step order. They contain no customer data and are marked not for production.
